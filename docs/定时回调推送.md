# 定时回调推送（计划推送）

## 概述

定时回调推送是数据中转流程的最后一环：当 B 公司（目标渠道）完成订单处理后，本系统将完整订单数据**回推给 A 公司（来源渠道）**。该功能通过 Laravel Artisan 命令 `callback:push-pending` 实现，由系统定时任务触发执行。

## 触发方式

命令签名：`callback:push-pending`

```
php artisan callback:push-pending
```

由操作系统级 cron / 任务计划程序按固定频率（如每分钟）调用。服务端需配置 crontab：

```
* * * * * cd /path/to/project && php artisan callback:push-pending >> /dev/null 2>&1
```

## 执行流程

```
┌─────────────────────────────────────────────────────────────────┐
│                    callback:push-pending                        │
├─────────────────────────────────────────────────────────────────┤
│  1. 查询所有 auto_callback_enabled = true 的渠道                 │
│                          ↓                                      │
│  2. 遍历每个渠道，检查当前时间是否在时间段内（H:i）               │
│     ┌─ auto_callback_time_start ~ auto_callback_time_end        │
│     └─ 未配置时间段则始终执行                                    │
│                          ↓                                      │
│  3. 扫描该渠道待回调的 ForwardOrder                              │
│     ┌─ source_pid = 渠道PID                                     │
│     ├─ callback_status = 0（待回调）                            │
│     └─ created_at >= 48小时前（仅处理最近订单）                   │
│                          ↓                                      │
│  4. 逐条执行 pushCallback()                                     │
│     ├─ 获取回调地址：ForwardOrder.callback_url → 渠道.callback_url│
│     ├─ 查找关联的 ProductOrder（产品订单）                       │
│     ├─ 组装推送数据（订单数据 + 转发结果）                       │
│     ├─ 调用 PushService 统一推送                                │
│     ├─ 更新 ForwardOrder.callback_status / callback_response    │
│     └─ 同步更新 ProductOrder.sync_status / sync_error           │
│                          ↓                                      │
│  5. 输出汇总：共处理 X 条，成功 Y 条                             │
└─────────────────────────────────────────────────────────────────┘
```

## 渠道配置

在 `third_channels` 表中有以下与定时回调相关的字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| `auto_callback_enabled` | boolean | 是否启用定时回调推送（默认 false） |
| `auto_callback_cron` | string(20) | 定时回调 Cron 表达式（预留字段，当前代码未使用） |
| `auto_callback_time_start` | string(5) | 允许执行的时间段起点，格式 `HH:MM`（如 `09:00`） |
| `auto_callback_time_end` | string(5) | 允许执行的时间段终点，格式 `HH:MM`（如 `21:00`） |
| `callback_url` | string(500) | 订单推送地址（A 公司接收回调的 URL） |

**时间段控制逻辑**：
- 未配置 `time_start` 和 `time_end`：**始终执行**，不受时间限制
- 配置了时间段：仅当 `time_start <= 当前时间(HH:MM) <= time_end` 时执行
- 例如 `09:00 ~ 21:00` 表示仅在早 9 点到晚 9 点之间推送回调

## 核心方法：pushCallback()

```php
protected function pushCallback(ForwardOrder $forwardOrder, ThirdChannels $channel): bool
```

### 推送数据组装

1. 从 `ProductOrder` 获取完整订单数据
2. 移除内部字段：`id`、`sync_status`、`pushed_at`、`sync_error`、`link_id`、`trace_id`、`product_id`、`business_id`、`channel_id`、`organization_id`、`deleted_at`、`created_at`、`updated_at`、`ext_json`、`internal_amount`、`settlement_id`、`settle_status`
3. 追加转发结果字段：
   - `forward_id` — 中转记录 ID
   - `forward_status` — 转发状态（0待处理/1成功/2失败）
   - `target_order_no` — 目标系统订单号
   - `callback_processed_at` — 回调处理时间

### 推送结果判定

使用 `PushService::send()` 统一处理，按优先级判定：

1. **成功规则匹配**（`push_success_rule`）→ 成功
2. **失败规则匹配**（`push_fail_rule`）→ 失败
3. **HTTP 2xx** → 成功
4. **其他** → 失败

### 状态更新

| 结果 | ForwardOrder 变更 | ProductOrder 变更 |
|------|-------------------|-------------------|
| 成功 | `callback_status=1`, `callback_response=响应体` | `sync_status=1`, `pushed_at=now()`, `sync_error=null` |
| 失败 | `callback_status=2`, `callback_response=响应体` | `sync_status=2`, `sync_error=错误信息` |

## 前序条件

ForwardOrder 进入待回调状态（`callback_status=0`）的时机：

1. **数据中转创建时**：`ReceiverController` 在创建 ForwardOrder 时默认 `callback_status=0`
2. **转发完成后**：`dispatchCallback()` 在 B 公司返回结果后，将完整订单数据推送到 A 公司
3. **验证码流程完成后**：首次订购验证通过后，`executeCallbackPush()` 推送结果

## 错误处理

- 单条推送失败**不会中断**整体流程，继续处理下一条
- 异常被 `try-catch` 捕获，记录到 `push_failure` 日志通道
- 已推送过的订单（`callback_status != 0`）不会被重复扫描（48 小时窗口内）

## 日志

| 场景 | 日志通道 | 级别 |
|------|---------|------|
| 无推送地址 | push_failure | WARNING |
| 未找到产品订单 | push_failure | WARNING |
| 推送成功 | push | INFO |
| 推送失败 | push_failure | WARNING |
| 推送异常 | push_failure | ERROR |
| 任务完成汇总 | 默认 | INFO |
