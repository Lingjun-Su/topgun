# 2026-09-03 · 渠道管理全配置化接入（工作日志）

时间：2026-09-03
主题：渠道管理作为唯一接入总控 —— 接入任意数量 A/C 不改代码
范围：前端 Quasar2（frontend/）+ 后端 Laravel（backend/）+ 设计文档

---

## 一、背景与目标

当前不同公司（对 B 而言 A/C 皆为外部数据源）的入站数据格式各异，系统缺少"外部格式 → B 内部契约"的适配层，导致：

- 收单（store / verifySubmit）强制外部提交内部字段名，不符即 422；
- 接入新公司需定制代码，违背"仅数据配置接入"的硬约束。

**目标**：凡新增 A/C 公司，只需在【渠道管理】配置该渠道行的通讯/入站映射/出站映射/产品授权即可上线，运行引擎零改动、零发版。

## 二、关键决策（沟通结论，提炼）

1. **A/C 同表、role 区分**：上游 A=`supplier_a`、下游 C=`channel_c`、未分类=`unset`，与 method 正交。
2. **业务→上游 A 定位**：`business.org_id == third_channels.organization_id`（role=supplier_a），复用现有字段，无需新表。一个 C 可运营多个 A 的产品，按订单走不同 A。
3. **入站统一范式**：对 B 而言所有外部数据统一经"入站映射 receive_mapping"翻译为 B 参考模型字段，再走既有校验与落库；原始 payload 留痕（source_data/ext_json）。
4. **全配置化**：一切差异进渠道行；新公司接入 = 建渠道 + 配产品授权 + 填映射（receive_mapping/request_mapping），不改代码。
5. 本轮采纳：只出方案+步骤，暂不实施映射引擎主体；已先落地渠道管理页面 UI 微调与 role 修复。

## 四、待实施：渠道管理全配置化 修改步骤

### 阶段 A｜入站映射基础设施

**A1 数据层**
- 新增迁移：`third_channels` 加 `receive_mapping`（JSON 列，渠道行内，按"入口"分段：order/verify/[callback]）。
- `ThirdChannelRequest` 校验 `receive_mapping` 为 `array` 且结构合法。
- `getFormattedDetail` 返回 `receive_mapping` 供编辑回显。

**A2 后端映射引擎**
- 新增 `App\Services\ThirdChannel\InboundMapper`（或扩展现有 `DataMapper` 增加 `mapForReceive`），支持表达式：
  - 直接字段 / 嵌套路径（`data.orderInfo.phone`）/ 候选回退（`a|b`）/ 固定值 / 默认值 / 忽略；
  - 转换器白名单：datetime 格式归一、numeric/int/bool 强转、enum 枚举映射、concat 拼接；
  - `__raw__` 透传未映射字段到 ext_json；
- 加载 `receive_mapping` 走缓存（随渠道更新 `clearCacheAfterUpdate` 失效）。

**A3 收单/验证码入口前置映射**
- `ReceiverController::store`：取原始 payload → `mapForReceive(order 段)` → 再走 `ProductOrderRequest` 严格校验 → 落库 + 原始留痕。
- `ReceiverController::verifySubmit`：`mobile/linkId/smsCode/bus_code` 同样经 `mapForReceive(verify 段)` 取值后，复用现有校验/并发锁/状态机。

### 阶段 B｜渠道管理前端

- 前端渠道行新增 `receive_mapping` 可视化编辑器：置于"接收配置"Tab，入口分段器（order/verify）→ 每段"内部字段 ← 外部来源/表达式"映射表；内置直接字段 / 嵌套路径 / 候选 / 固定值 / 默认 / 忽略 / 转换器下拉。
- 保存/回显走 `receive_mapping` 字段；与既有产品配置、推送配置共同构成"一个渠道一个接入档案"。

### 阶段 C｜回调方向收敛（可选）

- A→B 异步回执 `field_mapping` 并入 `receive_mapping`（以 callback 入口段），收敛 `ProvinceOrderInterpreter::applyFieldMapping` 到同一引擎，减少两套映射语义。

### 阶段 D｜接入流程与文档

- 新公司接入操作手册：①建渠道(名称/PID/Key/role/org/状态) → ②配产品授权 → ③填 receive_mapping(格式不符时) → ④配出站 push_base_url+push_steps.request_mapping → ⑤测试环境联调 getCode→submit。
- 产出 `receive_mapping` 表达式规范与字段清单一到 `docs/需求与设计/`。

### 阶段 E｜验收

- 至少模拟一家"字段名/嵌套/格式不一致"的外部方，仅靠渠道配置完成收单+验证码全流程，验证零代码改动。
