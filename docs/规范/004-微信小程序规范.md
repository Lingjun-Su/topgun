# 004 · 微信小程序规范

适用范围：微信小程序项目。小程序的接口调用与业务数据往往复用后端，需与后端规则（010 接口契约、006 枚举）保持一致。

## 目录结构

```
miniprogram/
  ├── app.js                 # 全局逻辑与全局变量
  ├── app.json               # 全局配置（页面、窗口、tabBar）
  ├── app.wxss               # 全局样式
  ├── pages/                 # 页面（每页一个目录：wxml/wxss/js/json）
  ├── components/            # 自定义组件
  ├── utils/
  │   ├── request.js         # 请求封装（统一 baseURL、token、拦截）
  │   └── enums.js           # 枚举与常量（映射展示，见 006）
  └── images/                # 图片资源
```

## 页面与组件

- 一个页面对应 `pages/` 下一个目录，含 `.wxml` / `.wxss` / `.js` / `.json` 四件套。
- 可复用的 UI 拆成 `components/` 自定义组件；数据与业务整理到 `utils/` 或引入的 store 平替（如全局 `getApp()` 数据）。
- 命名：页面目录 `kebab-case`，组件标签 `kebab-case`（`user-panel`），约状态用布尔加 `is`/`has` 前缀。

## 请求与鉴权

- 所有请求经 `utils/request.js` 封装，统一注入 token 与错误拦截，不裸写 `wx.request`。
- 登录态走 `wx.login` 换后端 token（Bearer），详见 010 接口契约。
- 受平台约束（如自定义 `request` 域名白名单），正式环境回调与请求白名单须与后端/资源台账一致。

## 兼容与体验

- 代码与 WXML 兼容微信基础库的合理最低版本，避免使用个别非通用调试特性。
- 长列表用分页，遵守 010 的分页约定；图片懒加载、缓存本地化提升体验。
- 用户隐私与授权（getUserProfile、收件地址等）按微信开放规则在触发时机申请，不越权采集。

## 枚举与向后端一致

- 状态/类型值以后端为准（见 006），小程序只做展示映射，不做业务判断。
