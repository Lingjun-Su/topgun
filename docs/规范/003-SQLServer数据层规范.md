# 003 · SQL Server 数据层规范

适用范围：SQL Server 数据层设计。

## 表与字段

- 表名用复数业务语义（`users`、`orders`），字段用 `snake_case`。
- 主键默认 `bigint identity`；业务确实需要自然键时单独在项目内约定并登记。
- 每张事实表提供 `created_at` / `updated_at`；审计类字段（`created_by` / `updated_by`）按业务需要扩展。

## 类型选择

| 场景 | 类型 | 说明 |
| --- | --- | --- |
| 文本（含中文） | `NVARCHAR` | 不用 `VARCHAR`，避免中文编码隐患 |
| 时间 | `datetime2` | 精度精确，不用旧 `datetime` 混淆语义 |
| 金额 | `decimal` | 精确十进制，禁浮点存钱 |
| 布尔 | `bit` | 语义即布尔，不用 `int` 0/1 |
| 主键 | `bigint identity` | 默认主键形态 |

## 索引

- 外键列必建索引，避免关联走全表扫描。
- 高频查询按覆盖查询建索引（`include` 拉取所需列）。
- 避免重复索引与冗余索引；索引变更随迁移管理、可回滚。

## 迁移与变更

- 结构变更走迁移脚本管理，禁止手工改生产库。
- 破坏性结构变更（删列、改类型）必须先在测试库演练，并在变更日志留痕。

## 存储过程

- 仅限复杂事务或批量计算使用；普通业务查询走应用层（Laravel Service/Repository）。
- 每个存储过程在项目中登记"用途"，便于审计与维护。

## 软删除与审计

- 软删除用 `deleted_at` 列 + 应用层软删除机制，不物理删业务数据（归档策略另行约定）。
