# 命名规范
Quasar框架自身并未在官方文档中强制执行单一、严格的文件命名规则，但为了确保项目的清晰性和可维护性，社区和官方工具在实践中形成了明确的惯例。

以下是根据官方项目结构和最佳实践整理的核心文件命名与目录规范：

### 📁 Quasar 项目文件命名与目录规范

| 项目 | 位置/类型 | 命名惯例与规则 | 说明与示例 |
| :--- | :--- | :--- | :--- |
| **项目目录** | `/src/` 下的核心目录 | 使用固定的**复数形式**名词。 | `assets/`, `components/`, `pages/`, `layouts/`, `boot/` |
| **页面组件** | `/src/pages/` | 使用**帕斯卡命名法 (PascalCase)** 或**串式命名法 (kebab-case)**，与Vue组件命名一致。 | `UserProfile.vue` 或 `user-profile.vue` |
| **布局组件** | `/src/layouts/` | 使用**帕斯卡命名法 (PascalCase)** 或**串式命名法 (kebab-case)**。 | `MainLayout.vue` |
| **通用组件** | `/src/components/` | 使用**帕斯卡命名法 (PascalCase)** 或**串式命名法 (kebab-case)**。 | `BaseButton.vue` |
| **启动文件** | `/src/boot/` | 使用**串式命名法 (kebab-case)** 描述其功能。文件名在 `quasar.conf.js` 中引用。 | `axios.js`, `i18n.js`, `router-auth.js` |
| **静态资源** | `/public/` | 全部使用**小写字母**，单词间可用连字符 `-`。**确保引用时大小写完全一致**，尤其在Vite模式下。 | `logo.png`, `company-icon.svg` |
| **动态资源** | `/src/assets/` | 通常全部使用**小写字母**，单词间可用连字符 `-`。在代码中引用时，建议使用 `~assets/` 别名。 | `app-header-bg.jpg` |
| **Vuex Store 模块** | `/src/store/` 目录下的文件夹 | 使用能描述其状态的**串式命名法 (kebab-case)** 文件夹名。模块文件通常命名为 `index.js`。 | `/store/user/` 下存放 `index.js`, `actions.js` 等。 |

### 💡 重要实践建议

1.  **使用Quasar CLI创建文件**：这是确保文件被放置在正确目录并遵循命名约定的最佳方式。例如：
    ```bash
    quasar new page AboutUs           # 在 /src/pages/ 创建 AboutUs.vue
    quasar new layout MainSidebar     # 在 /src/layouts/ 创建 MainSidebar.vue
    quasar new boot i18n              # 在 /src/boot/ 创建 i18n.js
    ```

2.  **统一大小写，避免问题**：强烈建议所有**目录名、文件名、资源引用**都采用**全小写**，并用连字符 `-` 分隔单词。这能从根本上避免在大小写敏感的系统（如Linux生产环境）或构建工具（如Vite）下出现路径错误。

3.  **保持命名表意清晰**：名称应能清晰表明文件或目录的用途，优先使用英文单词，避免使用拼音或缩写。

总结来说，遵循“**目录用固定复数、组件用帕斯卡/串式、文件用小写连字符**”这套惯例，能让你的Quasar项目结构清晰、协作顺畅。

如果你在特定的构建模式（如SSR或Electron）下有更具体的文件组织问题，可以进一步提问。
