# 前后端统一响应与业务状态码规范文档 (V1.0)

## 1. 设计理念

本系统采用 **“双层状态监控”** 模式：

1. **HTTP 状态码**：反映网络与服务器层面的连通性（如 200 正常，401 授权失败，500 服务器崩溃）。
2. **业务状态码 (Business Code)**：反映业务逻辑的执行细节（如 200 完全成功，206 部分成功，400 业务拦截）。

## 2. 后端规范 (Laravel 12)

### 2.1 统一响应性状 `ApiResponse` Trait

通过 `Trait` 将响应逻辑从控制器中抽离，实现高度复用。

**位置：** `app/Traits/ApiResponse.php`

```php
<?php

namespace App\Traits;

/**
 * 统一 API 响应插件
 */
trait ApiResponse
{
    /**
     * 成功响应 (All Success)
     * 用于常规 CRUD 操作
     */
    protected function success($data = [], $message = '操作成功', $code = 200)
    {
        return response()->json([
            'code'    => $code,
            'status'  => 'success',
            'message' => $message,
            'data'    => $data
        ], 200);
    }

    /**
     * 部分成功响应 (Partial Success)
     * 用于批量操作，结果中包含成功和失败的混合明细
     */
    protected function partial($successData = [], $failData = [], $message = '部分操作成功')
    {
        return response()->json([
            'code'    => 206,
            'status'  => 'partial',
            'message' => $message,
            'data'    => [
                'success_items' => $successData,
                'fail_items'    => $failData,
                'counts'        => [
                    'success' => count($successData),
                    'fail'    => count($failData)
                ]
            ]
        ], 200);
    }

    /**
     * 错误响应 (Logic Error)
     * 用于业务逻辑校验未通过
     */
    protected function error($message = '操作失败', $code = 400, $data = null)
    {
        return response()->json([
            'code'    => $code,
            'status'  => 'error',
            'message' => $message,
            'data'    => $data
        ], 200);
    }
}

```

### 2.2 控制器基类配置

在 `app/Http/Controllers/Controller.php` 中引入 Trait，使所有控制器自动具备响应能力。

## 3. 前端规范 (Vue3 + Quasar 2.18.6)

### 3.1 统一拦截器 `axios.js`

在响应拦截器中根据 `code` 自动触发 UI 提醒，减少页面组件的冗余代码。

**关键逻辑说明：**

* **200 (Success)**: 若为 `POST/PUT/DELETE` 请求，自动触发 `Notify.positive`。直接返回 `data` 层。
* **206 (Partial)**: 触发 `Notify.warning`，并返回数据主体。
* **401 (Unauthorized)**: 清除 Token，弹出对话框并跳转登录页。
* **403/400 (Error)**: 自动触发 `Notify.negative` 并执行 `Promise.reject`。

## 4. 业务状态码 (Code) 字典

| 状态码 | 语义 | 场景举例 | UI 表现 |
| --- | --- | --- | --- |
| **200** | **完全成功** | 数据查询成功、单条数据保存成功 | 静默(GET) 或 绿色提示 |
| **206** | **部分成功** | 批量推送订单，部分成功，部分因逻辑报错失败 | 黄色警告 + 结果明细 |
| **400** | **业务错误** | 账户余额不足、订单状态已锁定不可改 | 红色报错弹窗 |
| **401** | **认证失败** | Token 过期、未登录访问受保护接口 | 弹窗提示并跳转登录 |
| **403** | **拒绝访问** | 无权限操作该功能、或需更高级别验证 | 严谨的对话框提示 |
| **422** | **参数校验** | 表单填写格式不正确（Laravel Validator 触发） | 输入框下方红字提示 |
| **500** | **系统崩溃** | SQL 语法错误、PHP 运行报错 | 红色报错“系统繁忙” |

## 6. 审计规范 (Data Audit)

* 所有非 **200** 状态码的写操作请求（POST/PUT/DELETE），必须记录至 `audits` 表。
* `audits` 表应记录：`user_id`, `ip`, `request_payload`, `response_code`, `response_message`。
