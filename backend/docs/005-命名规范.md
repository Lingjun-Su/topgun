# 005 · 命名规范

适用范围：所有技术栈。约定命名在跨项目、跨团队间保持一致，避免同一概念在不同地方叫法不一。

## 各层命名形态

| 语义 | Laravel | Quasar2 / JS | SQL Server | 微信小程序 |
| --- | --- | --- | --- | --- |
| 类 / 组件 | `UserService` | `UserCard` | — | `user-panel` |
| 函数 / 方法 | `getUser()` | `getUser()` | — | `fetchUser()` |
| 变量 | `$userName` | `userName` | — | `userName` |
| 常量 | `MAX_RETRY` | `MAX_RETRY` | — | `MAX_RETRY` |
| 数据库表 | `users`（模型复数映射） | — | `users` | — |
| 数据库字段 | `updated_at` | — | `updated_at` | — |
| 布尔 | `$isActive` | `isActive` | `is_active` | `isActive` |

## 命名规则

- **类 / 组件**：`UpperCamelCase`（首字母大写的驼峰）。
- **函数 / 方法 / 变量**：`lowerCamelCase`（首字母小写的驼峰），动词开头、语义封闭，如 `createOrder`、`isExpired`。
- **常量**：`UPPER_SNAKE_CASE`（全大写下划线）。
- **数据库表与字段**：`snake_case`，表名用复数，字段名与后端模型属性驼峰版一一对应（`user_name` ↔ `$userName`）。
- **环境变量**：`域名_模块_键`，全大写，如 `ORDERS_DB_HOST`。
- **接口路径**：`/api/v{n}/{resource}`，资源名复数、路径小写短横线，如 `/api/v1/orders/{id}`。

## 宾语优先原则

命名尽量"动作 + 受动者"，让调用处读起来像一句完整的话：

- 好：`approveOrder`、`getOrderList`、`isUserActive`
- 差：`handleThings`、`do`、`data1`

## 保留与禁用

- 不使用单个字母（循环变量 `i`、`j` 除外）与拼音缩写。
- 不缩写常见词（`user` 不写 `usr`）；缩写只用于行业公认词（`id`、`url`、`api`）。
- 同一含义在同一仓库内只保留一种叫法，避免 `user` / `member` / `account` 混用（以领域建模界定为准）。
