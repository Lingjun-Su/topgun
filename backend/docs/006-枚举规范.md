# 006 · 枚举规范

适用范围：所有技术栈。枚举是业务状态/类型/类别在系统内的统一表达，必须全栈对齐、集中定义、稳定可扩展。

## 定义位置

- **后端（权威源）**：在 Laravel 中以 PHP 枚举类定义，集中在 `app/Enums/`，如 `app/Enums/OrderStatus.php`。数据库值以枚举字面量或映射表为准。
- **前端**：在后端生成/约定的枚举值上映射出只读常量，放在 `src/utils/constants.js`（或 `src/constants/`）。前端不做业务枚举的业务判断，只做展示映射。
- **微信小程序**：与前端一致，集中在 `utils/enums.js`，供页面与请求层复用。

## 命名

- 枚举类/类型：`UpperCamelCase` 单数名词（`OrderStatus`）。
- 枚举成员：`UPPER_SNAKE_CASE`（`PENDING`、`PAID`、`SHIPPED`）。
- 枚举值（持久化到库/传输）：使用**稳定的字符串或整数标识**，禁止用会随展示文案变化的汉字作为值。

## 后端定义示例（Laravel）

```php
// app/Enums/OrderStatus.php
enum OrderStatus: string
{
    case PENDING    = 'pending';
    case PAID       = 'paid';
    case SHIPPED    = 'shipped';
    case CANCELLED  = 'cancelled';

    public function label(): string
    {
        return match ($this) {
            self::PENDING   => '待支付',
            self::PAID      => '已支付',
            self::SHIPPED   => '已发货',
            self::CANCELLED => '已取消',
        };
    }
}
```

## 对齐与扩展

- **值一旦发布禁用改写**：已下发的枚举值代表线上契约，只能新增、不能修改已有值或语义。
- **扩展流程**：先改后端枚举并升级版本，再同步下发前端/小程序常量副本。
- **业务状态机**：状态间流转由业务层约束（见 `服务` 层），枚举只表达"当前是什么"，不表达"下一步能变为什么"。
- 行文不出现魔法裸值调用，一律引用枚举成员；展示文案由 `label()` 或前端映射统一产出。

## 需要建立枚举的常见场景

订单 / 支付状态、用户角色与权限、任务状态、审批状态、通用启停标志（is_active）、类型与分类、渠道/平台、错误码（见接口契约）。
