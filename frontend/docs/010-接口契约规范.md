# 010 · 接口契约规范

适用范围：后端（提供方）与前端/小程序调用方。

## 命名与风格

- 遵循 RESTful 资源语义：路径小写短横线（`kebab-case`），资源名用复数。
- 动作交给 HTTP 方法表达，路径里不放动词。
- 统一基路径前缀 + 主版本号：`/api/v1`。

| 方法 | 路径 | 语义 | 示例 |
| --- | --- | --- | --- |
| `GET` | 集合 | 列表/分页 | `GET /api/v1/orders` |
| `GET` | 单项 | 详情 | `GET /api/v1/orders/{id}` |
| `POST` | 集合 | 创建 | `POST /api/v1/orders` |
| `PUT/PATCH` | 单项 | 整体/局部更新 | `PATCH /api/v1/orders/{id}` |
| `DELETE` | 单项 | 删除/软删除 | `DELETE /api/v1/orders/{id}` |

## 鉴权

- 受保护接口统一 **Bearer Token（JWT）**，随请求头 `Authorization: Bearer <token>` 传递。
- 细粒度权限由后端作用域或 RBAC 判定；跨系统 OAuth2 授权由资源台账单独登记授权方与回调地址。

## 统一返回结构

成功与失败都返回同一个信封结构，客户端只解析约定字段：

```json
// 成功
{ "code": 0, "message": "ok", "data": { }, "trace_id": "a1b2c3" }
// 失败
{ "code": 41001, "message": "订单不存在", "data": null, "trace_id": "a1b2c3" }
```

| 字段 | 说明 |
| --- | --- |
| `code` | 业务码，`0` 表示成功，非 0 表示失败（见错误码） |
| `message` | 人类可读提示，可用业务语言直接展示给用户 |
| `data` | 业务数据载荷；分页时承载 `total` / `page` / `page_size` |
| `trace_id` | 本次请求链路追踪标识，必带，用于定位问题 |

## 错误码体系

码按段分配，段内预留扩展：

| 码段 | 类别 | 典型码 | 含义 |
| --- | --- | --- | --- |
| `0` | 成功 | `0` | 请求成功 |
| `1xxx` | 通用 | `10001` `10002` | 请求体非法 · 资源不可达 |
| `2xxx` | 认证授权 | `20001` `20002` `20003` | 未认证 · 令牌过期 · 无权限 |
| `3xxx` | 参数 | `30001` `30002` | 字段缺失 · 格式错误 |
| `4xxx` | 业务规则 | `41001` | 资源不存在 / 状态不允许，随业务扩展 |
| `5xxx` | 服务端 | `50001` `50002` | 内部错误 · 依赖服务超时 |

新业务错误码分配后回填到本项目的资源台账，保持全局唯一，不与旧码重复。

## 分页 · 排序 · 过滤

- 分页：`page`（从 1 起）与 `page_size`（上限 200）；响应 `data` 内附 `total` / `page` / `page_size`。
- 排序：`sort` 逗号连接，字段前缀 `-` 表示降序：`sort=-created_at,id`。
- 过滤：与字段同名的键值对承载；复杂组合由后端提供封装好的查询参数，不在 URL 塞嵌套表达式。
- 时间统一 **ISO 8601**（UTC 带偏移）传输；金额用分或字符串，避免浮点误差。

## 兼容与幂等

- 返回结构只加字段不删字段，保持向后兼容；破坏性变更必须升级主版本。
- 写操作（创建/支付等）前后端约定幂等键，避免重复提交造成脏数据。
