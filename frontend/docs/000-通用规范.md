# 000 · 通用规范

适用范围：所有技术栈。以下原则作为各技术栈专属规则的基础。

## 命名即文档

- 标识符自解释：读名即知其意，不靠注释补救含义。
- 与领域用语一致：业务中的叫法在代码、接口、表里保持同一个词。

## 注释只写为什么

- 不解释某段代码"做了什么"——那由命名与结构表达。
- 只记录非显见的约束、取舍、历史原因或外部依赖的坑。

## 消灭魔法值

- 字面量全部集中在常量/配置中管理。
- 禁止在业务代码中散落裸数字与裸字符串。
- 语义相同的值必须复用同一个常量源，不允许两处各自定义。

## 单一职责

- 类、函数、组件、方法只做一件事，过长即拆分。
- 每一层只负责自己的边界：HTTP 层不问业务，业务层不碰 HTTP 细节。

## 错误面向两端

- 用户看到可读提示，日志留足上下文（含 trace_id）。
- 禁止吞异常、禁止空 catch；处理不了就向上抛，不假装成功。

## 依赖与入口

- 优先依赖注入与显式传参，减少对全局状态的隐式依赖。
- 数字金额一律用精确十进制（分或 decimal），禁止浮点算钱。

## 代码风格基调

- 缩进统一（后端/脚本 4 空格，前端 2 空格），与各栈对应规范一致。
- 提交前保证本模块可运行、可构建，不留半成品。
